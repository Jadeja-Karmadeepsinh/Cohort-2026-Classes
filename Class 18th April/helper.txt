13. The beautiful part: Auth and IPL remain independent

Imagine your authentication module knows:

{
userId: "123",
role: "admin"
}

That's basically all the IPL module needs.

It doesn't care whether the user authenticated using:

email/password

or later:

Google OAuth

or:

GitHub OAuth

The Auth module says:

"This is user 123 and they're an admin."

The IPL module says:

"Admins can modify IPL data."

That's separation of concerns.

14. And this project will teach you a LOT of MongoDB

This project is actually perfect for the MongoDB concepts you've been learning recently.

You'll encounter:

References
Player → Team
Match → Team
Match → Venue
Match → Season
populate()

For example:

Player.find().populate("team");

So instead of receiving only:

{
"name": "MS Dhoni",
"team": "67abc..."
}

you can retrieve the team information too.

Projection

You might have:

Player.find()
.select("name role team");

instead of returning every field.

Aggregation

This project will give you real reasons to use aggregation.

For example:

"Show the top 10 run scorers."

or:

"How many matches has each team won?"

or:

"Calculate a player's total runs across all matches."

or:

"Show the points table."

Now aggregation isn't just some MongoDB syntax you're memorizing — you have an actual reason to use it.
